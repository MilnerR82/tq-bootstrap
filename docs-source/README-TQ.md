## Accessibility and installation corrections

The missed-work audit authorized a small, separate accessibility layer. Original Bootstrap CSS interfaces and JavaScript bundles remain available. The documentation and local examples load the separate TQ layer after Bootstrap and before initializing enhanced components. It manages tooltip hover/focus/Escape, paused carousel startup and explicit Play/Pause (plus native Previous/Next buttons for slides-only examples that otherwise have no navigation), and persistent form errors with field associations and an error summary. See [integration instructions](../docs/INTEGRATION.md) for loading order, module APIs, disposal and author responsibilities.

Both dashboard examples provide a named chart, description and keyboard-operable native data disclosure containing the exact seven plotted values. The theme control occupies its own normal-flow row only on the bottom-navbar and navbar comparison examples, resolving the measured control collision. Scrollable code blocks receive named keyboard regions only while their actual content overflows; the observer reassesses viewport/font/text-size changes. Ordinary bright links/outline controls use explicit native contrasting surfaces, and list metadata retains readable opacity. Numeric-opacity samples preserve their true utility values on empty decorative colour blocks while fully opaque labels remain readable. The Reboot 50% link demonstration is explicitly inactive. Live previews, copied markup and editor exports use the same accessible fixture markup.

The homepage and download documentation point to the actual local TQ downloads and CSS integration. Public package-manager commands and external hosted starters are explicitly labelled as upstream Bootstrap, with stock colours. No TQ package has been published to npm or an external starter service. Native hosted search, external imagery, outbound links and hosted starters may need a network connection. This is not a claim of universal WCAG conformance.

Header and Search keyboard focus is measured against its actual light, dark and supported forced-colour surfaces. The nested colour-mode demonstrations retain native ring dimensions with contextual ink, and the printed custom-mode Sass recipe uses the same opaque focus paint as its live example. Native Firefox search-caret screenshot limitations and automated WebKit implicit-link Tab policy are recorded as pending observations, not inferred passes. Actual NVDA and Safari/VoiceOver review remains pending.

The final encoded inline SVG scan also records the custom breadcrumb divider fill in `../qa/results/inline-svg-colour-substitutions.json`. Its TQ bright-red accent is measured above 3:1 on white and charcoal, with the original SVG dimensions/path and generated copyable markup preserved.

## Deployment origin

The default preview origin is `http://127.0.0.1:5198`. Before publishing, set `baseURL` in `docs-source/config.yml` to your own HTTPS origin and rebuild; inspect generated canonical URLs and local asset/download paths on that host. The build does not ship the upstream `getbootstrap.com` CNAME. If your host requires a CNAME, create it only with the domain you own and have configured for that deployment. Do not publish the local preview canonical origin as your public site identity.
