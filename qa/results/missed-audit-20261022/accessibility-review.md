# Independent accessibility omissions review — 22 October 2026

This review found missed accessibility issues. The existing design-preservation, supported-palette and functionality suites do not establish WCAG 2.2 AA conformance.

## What was measured

- **176/176 published routes** scanned as full documents in Chromium, 1440×1000, light mode, with axe-core 4.12.1 and WCAG 2 A/AA, 2.1 A/AA and 2.2 AA tags. No demo or footer exclusions. Redirects are recorded at their actual final destination (152 unique final URLs).
- **16 additional full-document axe states**: eight selected pages at 320px in light/dark modes, plus audit-only text-spacing and reflow measurements.
- **15 native behaviour measurements** and **9 confirmation measurements** across Chromium, Firefox and WebKit. No product markup, CSS or framework JavaScript was changed.
- Published HTML/CSS/JavaScript fingerprints are unchanged before/after the broad scan. The targeted and confirmation product fingerprints are also unchanged. Chart.js and Masonry loaded from fetched original bytes with matching original SRI; requested remote fonts/images were available. Hosted search/editor/analytics services were blocked and remain untested here.

The broad scan records **254 rule occurrences / 1032 flagged nodes across 153 route visits**, and **293 incomplete rule occurrences**. These are raw candidates, including redirect duplicates, inherited examples and intentionally unsupported colour combinations. They must not be presented as 1032 distinct TQ bugs. See [full raw scan](accessibility-scan.json), [searchable candidate index](accessibility-index.json) and [same-version rule metadata](axe-rule-metadata.json).

## Unfinished conformance evidence

The current release guide explicitly says it is not a complete WCAG evaluation. Its known omissions include NVDA, Safari/VoiceOver and actual browser/device zoom tests. The 320px viewport probe is useful reflow evidence, but it does not constitute an actual 400% browser zoom test. Text-spacing checks here are targeted geometry observations, not a complete clipped-content/manual review. No whole-site 200% text-resizing, forced-colours, complete assistive-technology or all-workflow assessment has been established.

The full criterion-by-criterion WCAG 2.2 A/AA assessment requested in the original plan was not part of the current release acceptance evidence. The later colour-only requirement preserves native Bootstrap behaviour, including these inherited limitations. Fixing native interaction/markup gaps would require explicit scope reconciliation; the new colour regressions can be corrected within colour-only scope.

WCAG assesses complete pages/processes, and automated tests cover only part of its requirements. [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/#conformance-reqs) defines those conformance requirements. [Bootstrap's own accessibility guidance](https://getbootstrap.com/docs/5.3/getting-started/accessibility/) also states that accessibility depends on author markup, style choices and scripting. Neither reference grants conformance to arbitrary framework combinations.

## Reproduce

With the current package installed and preview running at port 5198, run the accessibility-scan.mjs, targeted-accessibility.mjs and behaviour-confirmation.mjs helpers in qa/results/missed-audit-20261022/ using Node. They write only into this audit directory. The final summariser reads immutable raw outputs and adds an index; it does not change recorded observations.
