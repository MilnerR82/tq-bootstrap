## Other current failures, also present in the native baseline

These remain actual published-page accessibility limitations. A failed native baseline does not make a TQ page conformant, but it does distinguish retained Bootstrap behaviour from a newly introduced theme regression.

- **Source-file toolbar links in dark mode:** `.bd-file-ref .highlight-toolbar > a.link-secondary` is`#696567` on a composited`#302c2e` surface at**2.398:1**. The20-page dark sweep reports79such nodes across16pages. Native CSS is also below4.5at3.538:1. Examples include the exact spacing page currently under review. Templates: `docs-source/site/src/components/shortcodes/ScssDocs.astro:60` and`JsDocs.astro:58`.
- **Four inline prose links in the common footer:** no persistent underline and link-to-surrounding-text distinction of**2.19:1 light /1.31:1 dark**, below the3:1 colour-only distinction alternative. The pinned native CSS has the same problem at2.22/1.57:1. Verified in3engines andbothmodes in`footer-paint-proof.json`. Template `docs-source/site/src/components/footer/Footer.astro:23`; stylesheet`docs-source/site/src/scss/_footer.scss:5`.
- **Navbar combinations:** muted light text on the red navbar is3.141:1; the Search outline-light label is4.117:1. The same native patterns also fail (2.358and4.270:1). Ordinary red links on warm-grey sample surfaces, dark secondary text and several opacity examples also need context-specific treatment. Deliberately diagnostic utility/opacity/outline examples are retained separately in the raw sweep rather than counted as conforming UI.

## Palette application and scope

Fresh source-literal review did not identify an unclassified blue/purple stock Bootstrap UI colour still applied to ordinary local controls. The remaining original Bootstrap gradients found by the literal scan belong to the original Bootstrap logo asset; `#712cf9` in the colour-mode MDX is instructional custom-colour code. Logos, photographs, artwork and instructional literals are declared preservation exceptions, not missing substitutions. Favicon mask paint, manifest/theme metadata and documentation UI tokens already use the intended red/white palette.

All40local example previews have explicit recorded source/image evidence; they are light desktop captures at1440×900, not separate captures of every dark/mobile/expanded state. Keeping a native Bootstrap gallery does not require thumbnails for every state, and the preview report discloses this limit.

The native homepage still displays `npm i bootstrap@5.3.8` / `npm install bootstrap@5.3.8`, and original npm/yarn instructions install stock Bootstrap rather than the independently packaged TQ theme. Explicit external starter projects (Vite, webpack, Parcel, React/Next, ESM and colour modes) remain hosted upstream projects. These are disclosed upstream-content/external-service boundaries in the existing README. They should not be described as TQ-themed example projects or a TQ package-install path.
