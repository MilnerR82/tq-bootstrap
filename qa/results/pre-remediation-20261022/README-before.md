# Colour-only Bootstrap audit

The framework changes only the TAFE Queensland colours from Bootstrap 5.3.8. Native component geometry, typography, spacing, radii, shadows, dimensions, responsive behaviour, motion, utility generation and Bootstrap JavaScript are preserved. Three narrow documentation functionality repairs are separately recorded below; they introduce no visual redesign.

## TQ semantic palette

Light-mode reading pages and the documentation header remain white, with Magpie Black reading text. TQ Red remains the primary action colour. Bootstrap's original role generation now supplies distinct coloured emphasis text, subtle backgrounds, borders, alerts and table variants instead of forcing every role onto the same neutral surface.

| Bootstrap role | TQ colour | Hex |
| --- | --- | --- |
| Primary | TQ Red | #E31B23 |
| Secondary | Magpie Black L1 | #696567 |
| Success | Barrier Reef Teal D2 | #00766C |
| Information | Barrier Reef Teal | #00A89B |
| Warning | Sunkissed | #FF4904 |
| Danger | Flame Tree Red D1 | #8A0008 |
| Light | Koala Grey L2 | #F1EFED |
| Dark | Outback Indigo | #091135 |

The blue family uses Outback Indigo L3 (#2F4370), indigo uses Outback Indigo, purple uses Jacaranda Purple D2 (#6C0162), and pink retains Eucalyptus Blossom (#F32A7C). Yellow intentionally aliases Sunkissed; green uses dark teal; teal and cyan share Barrier Reef Teal. These are documented brand adaptations of Bootstrap's existing colour interfaces.

Outback Indigo is the contrast-dark text choice on bright teal and orange solid controls; white and Magpie Black text alone do not meet 4.5:1 on both fills. The ordinary dark-mode body remains charcoal. Danger emphasis uses a lighter tint on dark reading pages, and the light-mode neutral dark alert uses Magpie Black text on Koala grey. Native validation glyph shapes remain unchanged: valid feedback uses a measured teal shade, invalid feedback uses vivid red, valid checked controls use success teal and invalid checked controls use danger red. Native disabled opacity is retained and inactive controls are not counted as active-control contrast passes.

Outline controls retain Bootstrap's original context requirement. Primary, secondary, success, danger and dark outlines use a white surface; info, warning and light outlines use the explicit Outback Indigo `bg-dark` surface. The ordinary charcoal body is insufficient for small bright-teal or orange outline text. The palette audit records 30 unsupported outline/body combinations separately; these are limitations, never passing contrast checks. Arbitrary utility/opacity/background combinations are not claimed to conform.

## Limits

This is an exhaustive compiled design-preservation audit with rendered comparison evidence, not a complete WCAG conformance assessment. Original Bootstrap non-colour defaults and accessibility requirements remain unchanged. Complete pages/processes still need appropriate content, labels, contrast choices, keyboard and assistive-technology review. No blanket WCAG 2.2 AA claim is made.

Installed Edge automation was blocked by organisation policy. Playwright WebKit is not Safari/VoiceOver. NVDA, Safari/VoiceOver and actual device/browser zoom checks are not claimed.

Native DocSearch/Algolia, StackBlitz, ads/analytics and external media are hosted services. The portability check verifies local framework assets and native modal behaviour with those requests isolated; it does not claim hosted features work offline. The original native header gradient geometry remains present, painted white in light mode.

Original logos and photos retain their original source colours. The 80 published gallery thumbnails are captures of the 40 real TQ examples at the native image sizes; original upstream thumbnail source files remain intact. Instructional CSS/Sass and native source-code excerpts remain upstream reference content. Live colour data and printed palette hex labels match the corresponding TQ tokens through exact RGB-only source substitutions; original names, classes, YAML contrast flags and layout are preserved. Live examples and generated copyable markup use the recorded TQ substitutions. External applications and media are outside the local theme.

## Repeating the audit

1. Install root build dependencies and documentation build dependencies using their pinned lockfiles.
2. Run `npm test` for compiled framework/native/official parity.
3. Run `npm run test:docs` for docs CSS parity and its generated comparison reference.
4. Start the local preview and run `npm run test:rendered`.
5. Run `node qa/font-stability-proof.mjs`, `npm run test:examples`, `node qa/example-contrast.mjs`, `node qa/palette-contrast.mjs`, `node qa/palette-labels.mjs` and `npm run test:sass` for font readiness, standalone source/paint/rendered, changed-combination contrast, semantic palette/context checks, live label consistency and Sass-interface checks.
6. Run `node qa/standalone-functionality.mjs`, `node qa/docs-functionality.mjs`, `node qa/docs-nested-functionality.mjs`, `node qa/snippet-export.mjs`, `node qa/example-links.mjs` and `node qa/version-scope.mjs` for the functionality, SDK payload, local route/copy-target and version-menu reviews. The exact header revision comparison requires its preserved pre-change workspace baseline; the release includes the resulting original subtree/hash evidence.
7. Run `node scripts/build-example-previews.mjs --verify` to verify the supplied gallery captures; omit `--verify` only when deliberately recapturing an updated, served build.
8. After creating the final ZIP, run `npm run test:portability`.
